# ИИ-агенты в жизненном цикле разработки

Набор документов о том, как встроить работу ИИ-агентов в разработку кода на проекте — на всех этапах: планирование, разработка, тесты, деплой, документация, эксплуатация. Фокус на закрытый контур: локальные open-weight модели, которые раздаются через **vLLM** по OpenAI-совместимому API.

Материал опирается на мировой опыт (Anthropic AI-native SDLC, agentic SDLC от Sonar/Port/CodeRabbit, context engineering, spec-driven development, OWASP LLM Top 10, документация vLLM). .



## Для кого

- Техлид / архитектор, который решает, где и как подключать агентов.
- DevOps / платформенный инженер, который поднимает vLLM и инфраструктуру агентов.
- Разработчики, которые будут работать бок о бок с агентами.


## Главный тезис

Когда агент пишет и переписывает код быстрее, чем человек успевает проверять pull request, **узкое место не исчезает, а смещается** — с написания кода на ревью, проверку и контроль. Поэтому зрелая практика строит не «автопилот», а **управляемый конвейер**: агенты выполняют работу внутри заданных границ (guardrails), а человек задаёт намерение, проверяет результат на ключевых точках и владеет решениями. Это и есть *agentic SDLC* / *AI-native SDLC*.

Три опоры, на которых всё держится:

1. **Harness (обвязка)** — среда, в которой агент работает: инструменты, права, тесты, линтеры, CI, обратная связь. Качество обвязки важнее «ума» модели.
2. **Context engineering (контекст-инжиниринг)** — что именно модель знает в каждый момент: `AGENTS.md`, спеки, правила, нужные (и только нужные) файлы.
3. **Guardrails + human-in-the-loop** — многослойная защита и точки, где решение остаётся за человеком.

## Терминология

- **Агент** — ИИ-процесс, который получает задачу, сам планирует шаги, вызывает инструменты (edit, run, test, git, MCP), читает обратную связь и итерирует до результата. Отличается от «ассистента-автодополнения».
- **Harness / обвязка** — исполняемая среда агента: доступные инструменты, права, тесты, линтеры, CI, песочница, обратная связь.
- **Context engineering** — управление тем, что модель видит в контексте в нужный момент (вместо «свалить всё сразу»).
- **AGENTS.md** — стандартизованный файл в корне репозитория с инструкциями, конвенциями и границами для агентов. «README для LLM».
- **Spec-driven development (SDD)** — спецификация (требования → дизайн → задачи) как главный артефакт; код — производное от спеки.
- **Guardrails** — многослойные ограничения: права на инструменты, запрет записи без подтверждения, политики, статический анализ, песочница.
- **Human-in-the-loop (HITL)** — обязательные точки, где решение/подтверждение за человеком (merge, деплой, запись в прод).
- **MCP (Model Context Protocol)** — протокол, через который агент получает доступ к внешним системам (Jira, Confluence, Bitbucket, базы) как к инструментам.
- **vLLM** — высокопроизводительный движок инференса LLM с OpenAI-совместимым API; раздаёт локальные open-weight модели.
- **Tool calling (function calling)** — способность модели вернуть структурированный вызов инструмента вместо текста.
- **Subagent (подагент)** — узкоспециализированный агент под один класс задач (ревью, тесты, безопасность), вызываемый оркестратором.
- **Уровень автономии** — степень самостоятельности агента: suggest → ask → auto-with-review → autonomous-in-sandbox.

## Как пользоваться комплектом

1. Определите текущий уровень зрелости и целевой — [документ 1](01-maturity-and-operating-model.md).
2. Выберите 1–2 этапа SDLC для пилота (обычно тесты и документация — низкий риск) — [документ 2](02-lifecycle-practices.md).
3. Разложите работу на роли агентов и подберите модели под железо — [документы 3](03-agent-roles-and-models.md) и [4](04-vllm-infrastructure.md).
4. Настройте контекст и guardrails до первого реального прогона — [документ 5](05-context-engineering-and-guardrails.md).
5. Запустите пилот, снимите метрики, расширяйте охват — [документ 6](06-rollout-metrics-antipatterns.md).
